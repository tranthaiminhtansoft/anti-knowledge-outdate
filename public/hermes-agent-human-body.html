HERMES AGENT · HUMAN MORPHOLOGY

Không phải sơ đồ module.
Đây là một con người đang suy nghĩ.

Mỗi user turn tạo một model request mới. Prompt Builder tạo cached SYSTEM từ các nguồn theo tier; AIAgent request assembly kết hợp SYSTEM với MESSAGES[] và trường TOOLS[] riêng. Trong luồng on-demand minh hoạ, Full Skill, RAG hay payload ngoài xuất hiện sau tool call; preload, plugin hoặc external-memory overlay có thể chèn sớm hơn.

SẴN SÀNG · TỰ BẤM START

FULL SKILL ≠ MCP RESULT

Một cái dạy cách làm; một cái thực thi để lấy kết quả.

Cả hai đều quay về MESSAGES[] qua agent loop, nhưng payload và mục đích hoàn toàn khác nhau.

FULL SKILL · HƯỚNG DẪN “LÀM THẾ NÀO”

Trước

System chỉ có Skill Index: tên + mô tả ngắn.

Model gọi

skill_view(name)

Nhận lại

Full SKILL.md: các bước, quy tắc và pitfall.

Sau

Model biết quy trình cần làm theo; chưa đồng nghĩa hành động ngoài đã chạy.

MCP · DỮ LIỆU / KẾT QUẢ HÀNH ĐỘNG

Trước

TOOLS[] chỉ có schema mô tả tool.

Model gọi

MCP tool_call

Nhận lại

MCP Result: dữ liệu thật, lỗi hoặc xác nhận hành động.

Sau

Model có evidence để kiểm chứng và trả lời; result không tự trở thành Memory.

Một tác vụ có thể dùng cả hai: Skill Index → skill_view → Full Skill hướng dẫn cách làm → Model gọi MCP theo hướng dẫn → MCP Result xác nhận điều đã đọc/làm → Model trả lời.

KHI PHÉP VÍ GẶP SỰ THẬT KỸ THUẬT

Hình người để dễ hiểu; hành vi vẫn phải đúng.

Prompt đi vào toàn bộ Agent

Direct UI có thể đưa prompt thẳng vào runtime. Gateway không bị vẽ như một cơ quan bắt buộc trong cơ thể.

Messaging gom channel, Bot và Gateway

Discord, Telegram hoặc Slack cùng logic Bot/Gateway nằm trong một máy tính tiếp nhận; traffic chỉ rời máy sau khi prompt đã được chuẩn hóa.

Skill Index khác Full Skill

Skill Index name + description nằm sẵn trong system message. Trong luồng on-demand, Model gọi skill_view để Full SKILL.md quay lại như Tool Result trong messages của lượt sau; preload có thể nạp Full Skill trực tiếp.

Các nguồn là các phần system độc lập

SOUL, Skill Index và active Profile hint thuộc stable tier; project files thuộc context tier; MEMORY.md và USER.md thuộc volatile tier. Prompt Builder ghép chúng ở first turn rồi cache toàn chuỗi.

Tool Schemas ở API field riêng

Tool definitions được gửi ở trường API riêng, không phải một chat message. Tool Result mới được runtime append vào conversation cho lượt Model kế tiếp.

Context window là toàn request Model thấy

System message, history, current prompt, tool results và tool schemas cùng dùng token budget. SYSTEM giữ nguyên trong normal tool loop, nhưng có thể rebuild sau context compression hoặc khi runtime identity đổi.
